Step 01 / Preprocessing

Clinical Preprocessing & FNA Features

Converting raw cytological aspirates into model-ready features requires structured standardization and domain-specific feature engineering. This ensures high stability and clinical relevance during model training.

1. Wisconsin Breast Cancer dataset

The Wisconsin FNA dataset contains 569 instances representing cell nucleus measurements extracted from fine-needle aspirates (FNA). Each nucleus has 10 core features (e.g. radius, perimeter, concavity), leading to 30 overall features representing mean, standard error, and worst values.

2. Z-Score Standardization

Because features like cell area are in thousands while smoothness measurements are in decimals, raw models would experience significant gradient bias. We standardise the inputs using Z-Score scaling:

z = (x - μ) / σ

Where μ is the training mean and σ is the training standard deviation, ensuring all final inputs scale to a zero mean and unit variance.

3. Domain-Specific Feature Engineering

To capture non-linear morphological relationships, we construct four highly informative engineered features:

1. Perimeter-to-Area Ratio (rpa)

Identifies cell border elongation and shape irregularity:

rpa = perimeter_mean / area_mean

2. Concavity-to-Points Ratio (cratio)

Evaluates the relationship between average structural indentations and cell irregularities:

cratio = concavity_mean / concave_points_mean

3. Radius worst deviation (Radius Growth)

Quantifies tumor cell size heterogeneity across samples:

Radius Growth = radius_worst - radius_mean

4. Compactness worst deviation (Compactness Growth)

Measures density structural packing deviations:

Compactness Growth = compactness_worst - compactness_mean

4. Data Preparation Code

To inspect how scaling and feature mapping are initialized, review the implementation snippet:

# Preprocessing implementation in train_model_enhanced.py
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

# Load dataset
df = pd.read_csv('breast-cancer.csv')
X = df.drop(columns=['id', 'diagnosis'])
y = df['diagnosis'].map({'M': 1, 'B': 0})

# Engineered Features
X['perimeter_area_ratio'] = X['perimeter_mean'] / (X['area_mean'] + 1e-8)
X['concavity_points_ratio'] = X['concavity_mean'] / (X['concave points_mean'] + 1e-8)
X['radius_growth'] = X['radius_worst'] - X['radius_mean']
X['compactness_growth'] = X['compactness_worst'] - X['compactness_mean']

# Split & Scale
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
Step 02 / Optimization

Bayesian Hyperparameter Optimization

We train an ensemble of five distinct base classifiers (LightGBM, XGBoost, Random Forest, Logistic Regression, and Gradient Boosting) and tune them using **Optuna** Bayesian optimization.

1. The Multi-Model Classifier Suite

Rather than relying on a single estimator, we train diverse modeling paradigms to balance performance and explainability boundaries:

  • XGBoost / LightGBM: High-performance decision-tree boosting architectures capturing non-linear feature splits.
  • Random Forest: High stability bagging method that reduces prediction variance.
  • Logistic Regression: Linear baseline classifier providing high interpretability comparison.

2. Bayesian Optimization with Optuna

We configure an objective function optimized via tree-structured Parzen Estimators (TPE) over a stratified 5-fold cross-validation scheme. This locates optimal parameters while preventing overfitting:

# Bayesian Tuning Objective
def objective(trial):
    params = {
        'n_estimators': trial.suggest_int('n_estimators', 50, 300),
        'max_depth': trial.suggest_int('max_depth', 3, 10),
        'learning_rate': trial.suggest_float('learning_rate', 0.01, 0.2, log=True),

Step 03 / Explainability

Multi-Method Explainer Foundations

We deploy four independent post-hoc explainability methods to capture local predictions from distinct mathematical perspectives (attributions, local surrogates, rules, and gradients).

SHAP (SHapley Additive exPlanations)

SHAP leverages cooperative game theory to distribute the payout (difference between prediction and baseline) fairly among features. It guarantees unique properties:

  • Efficiency: The sum of feature attributions equals the model prediction minus baseline output.
  • Symmetry: Identical features receive identical attributions.
  • Dummy: Features that do not affect the prediction receive zero attribution.
φi = ΣS ⊆ N \ {i} [ |S|!(|N| - |S| - 1)! / |N|! ] × [ v(S ∪ {i}) - v(S) ]

Where v(S) is the expected model prediction given the feature subset S.

LIME (Local Interpretable Model-agnostic Explanations)

LIME builds a local interpretable surrogate model (like a linear regression) by perturbing the target sample and measuring how predictions shift:

ξ(x) = arg ming ∈ G L(f, g, πx) + Ω(g)

Where:

  • L(f, g, πx) is the local unfaithfulness of the surrogate model g compared to base model f.
  • πx(z) is the exponential proximity distance kernel weighting perturbations:
πx(z) = exp( -D(x, z)2 / σ2 )

Anchor Explanations (High-Precision Rules)

Anchors discover local high-precision IF-THEN rules that guarantee the prediction remains unchanged within a defined neighborhood bounded by coverage:

Prec(A) = P( f(z) == f(x) | A(z) == 1 ) ≥ τ

Where A represents the set of rule predicates, and τ is the target precision threshold (usually 95%). This guarantees clear malignant/benign bounds like:

Example Anchor Rule: IF worst_concave_points > 0.147 AND perimeter_area_ratio < 0.082 THEN diagnosis is MALIGNANT (Precision: 98.4%, Coverage: 21.2%).

Integrated Gradients

Integrated Gradients aggregates gradients along a straight path from a baseline reference input (like zero features) to the target input, ensuring axiom completeness:

IGi(x) = (xi - x'i) × ∫01 [∂f(x' + α(x - x')) / ∂xi] dα

Approximated numerically via finite-difference Riemann sums:

IGiapprox(x) = (xi - x'i) / M × Σk=1M [∂f(x' + k/M × (x - x')) / ∂xi]
Step 04 / Ensemble

Unified Hybrid XAI Ensemble

Individual XAI methods can generate conflicting attributions due to their mathematical differences. We introduce a confidence-weighted ensemble algorithm to compute a stable consensus.

1. The Ensemble Algorithm

We normalize local attributions from SHAP, LIME, and Integrated Gradients, then weight them using model confidence and explanation fidelity scores:

Attributionensemble = wSHAP · φSHAP + wLIME · φLIME + wIG · φIG

Where the weights are dynamically calculated on the fly based on local method agreement scores.

Step 06 / Engineering

Multi-Mode Docker Containerization

To prepare ClinicalXAI for secure cloud deployment, we encapsulate all training and explanation assets in a containerized environment using a multi-mode entrypoint configuration.

1. Multi-Mode entrypoint.sh Workflow

We design a script that enables the same Docker container to function as either an **API serving endpoint** or a **Streamlit dashboard portal** based on an environment variable:

#!/bin/bash
# docker-entrypoint.sh
if [ "$APP_MODE" = "STREAMLIT" ]; then
    echo "Launching Streamlit Clinical Dashboard..."
    exec streamlit run dashboard.py --server.port=8501 --server.address=0.0.0.0
else
    echo "Launching FastAPI Serving Server..."
    exec uvicorn app_enhanced:app --host 0.0.0.0 --port 8000
fi

2. Dockerfile Design

The multi-stage Dockerfile installs core ML dependencies (SHAP, LIME, Optuna, Streamlit, FastAPI), compiles optimized models, and exposes ports 8000 and 8501:

# Dockerfile
FROM python:3.10-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000 8501
RUN chmod +x docker-entrypoint.sh
ENTRYPOINT ["./docker-entrypoint.sh"]
Step 07 / Cloud

Cloud Deployment (AWS + GCP)

For lock-down enterprise healthcare environments where local scripts are restricted, we establish manual console procedures for AWS and Google Cloud.

1. Google Cloud (Vertex AI) Manual Console Steps

  1. Artifact Registry Repo: Navigate to Artifact Registry, create a repository named xai-images, and push the Docker image: 
    gcloud auth configure-docker us-central1-docker.pkg.dev
docker tag xai:latest us-central1-docker.pkg.dev/my-project/xai-images/xai:v1
docker push us-central1-docker.pkg.dev/my-project/xai-images/xai:v1
  2. Import Model: Go to Vertex AI Models, click Import, specify container image, and configure prediction routes.
  3. Deploy Endpoint: Deploy model to an endpoint with n1-standard-4 instances for fast inference.

2. AWS (SageMaker) Manual Console Steps

  1. ECR Repository: Create an AWS Elastic Container Registry repository named xai/inference.
  2. CloudShell Image Build: Open CloudShell, pull the source, build and push to ECR: 
    IMAGE_URI="\${AWS_ACCOUNT_ID}.dkr.ecr.\${AWS_REGION}.amazonaws.com/xai/inference:v1"
docker build -t "\${IMAGE_URI}" .
docker push "\${IMAGE_URI}"
  3. SageMaker Endpoint: Go to SageMaker Models, create model referencing ECR URI, configure endpoint group, and launch.
CloudShell Space Recovery: If CloudShell hits a No space left on device error, prune docker caches: 
docker system prune -af --volumes
